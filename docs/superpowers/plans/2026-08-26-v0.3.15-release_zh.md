# v0.3.15 发布执行计划

> **面向 Agent 的要求：** 按本发布计划逐项执行并保留验证证据。任一门槛未通过，不得发布。

**目标：** 将已验收的 `v0.3.15` 功能分支作为 GitHub Release 发布，产出已验证的 DMG 与校验和。

**架构：** 先在功能分支准备受版本控制的发布元数据和用户文档，验证后合入本地 `main`，再从合并后的 `main` 打包。物理 `dist` app 在复制后可能被 Desktop/FileProvider 写入元数据，因此发布验收以最终 DMG 挂载出的 app 为准。

**技术栈：** Swift Package Manager、macOS `codesign`、`hdiutil`、`shasum`、Git、GitHub CLI。

## 全局约束

- 发布版本为 `0.3.15`，构建号为 `20`，Tag 为 `release/v0.3.15`。
- 在验证合并前只使用 `/Users/zbw/Desktop/API-inquiry/.worktrees/v0.3.15`；合并后在 `/Users/zbw/Desktop/API-inquiry` 的 `main` 上打包和发布。
- 测试使用 `swift run APIInquiryCoreTestsRunner`，不得使用 `swift test`；发布候选必须得到 `PASS: 679 expectations`。
- 只能使用伪造/Mock 测试数据，绝不打印凭据、access token、account id 或认证响应正文。
- 保留根 worktree 既有未跟踪的 `AGENTS.md`、`CLAUDE.md` 和 `docs/reviews/`；不得修改、复制、暂存、提交或删除这些文件。
- Credits 是现有 `/backend-api/wham/usage` 响应中的原始 `credits.balance` 用量单位；不得增加 endpoint、进行货币换算，也不得复用手动重置 credits 子系统。
- 只替换 OpenAI/Codex Console Home 的 `Status` 指标；保留顶部状态徽章、额度 `Detail`、Menubar 输出、详情页结构、窗口几何、圆角、材质、不透明度和透明度。其他供应商继续显示 `Status`。
- Credits 缺失、畸形或为负数时显示 `--`；Credits 无效不能丢弃有效的 5h/1W quota。即使 balance 畸形，`credits.unlimited == true` 仍显示本地化 Unlimited。
- 最终挂载出的 DMG app 未通过 `codesign --verify --deep --strict` 时，不得发布。
- GitHub Release 必须为非草稿、非预发布，并且只包含 DMG 与对应 `.sha256` 文件。
