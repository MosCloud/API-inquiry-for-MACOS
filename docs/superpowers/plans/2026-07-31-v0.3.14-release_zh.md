# v0.3.14 发布执行计划

> **面向 Agent 的要求：** 按本发布计划逐项执行并保留验证证据。任一门槛未通过，不得发布。

**目标：** 将已验收的 `v0.3.14` 功能分支作为 GitHub Release 发布，产出已验证的 DMG 与校验和。

**架构：** 先在功能分支准备所有受版本控制的发布元数据，验证后合入本地 `main`，再从 `main` 打包。物理 `dist` app 在复制后可能被 Desktop/FileProvider 写入元数据，因此发布验收以最终 DMG 挂载出的 app 为准，而不是延迟验证 `dist/API Inquiry.app`。

**技术栈：** Swift Package Manager、macOS `codesign`、`hdiutil`、`shasum`、Git、GitHub CLI。

## 全局约束

- 发布版本为 `0.3.14`，构建号为 `19`，Tag 为 `release/v0.3.14`。
- 测试使用 `swift run APIInquiryCoreTestsRunner`，不得使用 `swift test`。
- 只能使用伪造/Mock 测试数据，绝不打印凭据或 Codex 认证载荷。
- 保留根 worktree 既有的未跟踪 `AGENTS.md`、`CLAUDE.md` 和 `docs/reviews/`。
- 最终挂载出的 DMG app 未通过 `codesign --verify --deep --strict` 时，不得发布。
- GitHub Release 必须为非草稿、非预发布，并且仅上传 DMG 与对应 `.sha256` 文件。
