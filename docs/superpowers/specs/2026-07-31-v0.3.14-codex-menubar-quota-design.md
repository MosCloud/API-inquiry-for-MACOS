# API Inquiry v0.3.14 Compact Codex Menu Bar Quota Design

## Summary

v0.3.14 simplifies the menu bar value for the OpenAI/Codex quota provider. The menu bar shows one remaining percentage, such as `72%`, instead of including a quota-window label such as `5H 72%` or `1W 48%`.

The selected value still follows the existing priority: use the 5-hour window when it is available; otherwise use the available weekly window. Opening the menu bar panel continues to show every returned quota window with its localized label, remaining percentage, reset time, availability, and tone.

In the current provider registry, the user-facing OpenAI secondary label maps to the `.codex` provider and `CodexQuotaProvider`.

## Goals

- Create the v0.3.14 work on an isolated `v0.3.14` branch based on `main`.
- Show only `xx%` in the menu bar when Codex is the Primary Provider.
- Prefer the 5-hour quota when both 5-hour and weekly windows are available.
- Fall back to the weekly quota when the response contains no 5-hour window.
- Keep the clicked menu detail panel complete for both dual-window and single-window responses.
- Preserve existing behavior for DeepSeek, Zhipu GLM Coding Plan, Codex manual-reset credits, and all non-menu-bar surfaces.
- Cover the formatter boundary and provider-to-menu data flow with automated tests.

## Non-Goals

- Do not change the Codex endpoint, credential flow, or response schema.
- Do not change how `used_percent`, reset timestamps, or window durations are parsed.
- Do not redesign the menu detail panel or Console.
- Do not change localized detail labels, status text, amount tones, or reset-time formatting.
- Do not add a generic configurable menu-display policy for providers.
- Do not perform release packaging, tagging, or publication as part of this behavior change.

## Display Contract

| Returned recognized windows | Menu bar value | Clicked menu detail |
| --- | --- | --- |
| 5-hour and weekly | 5-hour remaining percentage, for example `72%` | One 5-hour row and one weekly row |
| 5-hour only | 5-hour remaining percentage, for example `72%` | One 5-hour row |
| Weekly only | Weekly remaining percentage, for example `48%` | One weekly row |
| No recognized usable window | Existing unavailable/error behavior | Existing unavailable/error behavior |

The menu bar does not reveal which recognized window supplied the percentage. The detail rows provide that context.

Percentages retain the existing formatter behavior: values are truncated to an integer before display. For example, `72.9` displays as `72%`.

## Design

### Window Selection

`ProviderValueFormatter.primaryQuotaWindow(in:)` remains the selection boundary:

1. Select the first window whose semantic kind is `.fiveHour`.
2. If no 5-hour window exists, select the first recognized window preserved by the provider.

`CodexQuotaProvider` derives window meaning from `limit_window_seconds`, not from whether the payload field is named `primary_window` or `secondary_window`. It preserves recognized 5-hour and weekly windows and rejects a response only when no recognized window remains. This allows a weekly-only payload such as a 604,800-second `primary_window` with `secondary_window: null`.

### Menu Bar Formatting

`ProviderValueFormatter.menuQuotaWindowText(for:)` remains the compact quota formatter used by `menuValueText`.

For recognized `.fiveHour` and `.week` windows, it returns only the formatted remaining percentage. A defensive unknown window keeps the existing `label xx%` form so an unexpected future value is not presented without context.

`MenuBarBalanceViewModel.menuBarValueText` and `menuBarTitle` continue to consume the formatter result. No provider prefix is added for Codex.

### Clicked Menu Detail

No detail rendering path changes.

`MenuBarBalanceViewModel.primaryQuotaWindowRows` continues to map every window in `QuotaUsageSnapshot.windows`. Each row keeps:

- Its localized 5-hour or weekly label.
- Remaining percentage and amount tone.
- Remaining suffix.
- Reset time or reset date.
- Availability state.

If both recognized windows are returned, both rows appear. If only the weekly window is returned, only the weekly row appears. Secondary-provider quota rows remain complete as well.

### Other Surfaces

`detailText`, `secondaryDetailText`, `consoleDetailText`, and `primaryDisplayParts` are unchanged. DeepSeek cash balance, Zhipu plan usage, Console summaries, and Codex manual-reset credits therefore retain their current output.

## Data Flow

1. `CodexQuotaProvider` decodes recognized quota windows into `QuotaUsageSnapshot.windows`.
2. `BalanceRefreshController` and `MultiProviderBalanceCoordinator` publish the loaded snapshot.
3. `MenuBarBalanceViewModel.menuBarValueText` requests the compact value.
4. The formatter selects the 5-hour window when present, otherwise the weekly window, and emits only `xx%`.
5. When the user opens the menu, `primaryQuotaWindowRows` independently maps all returned windows into detailed rows.

The compact menu value and detailed rows intentionally use separate presentation paths.

## Error Handling

Existing state and provider error handling remain unchanged:

- Not configured continues to show `Setup` or its localized equivalent.
- Loading without a previous snapshot continues to show `--`.
- Loading or failure with a previous snapshot continues to use the existing last-snapshot behavior.
- Authentication, rate limit, server, decoding, and missing-balance errors keep their current mappings.
- Unknown window durations remain filtered by the provider.

No new user-facing strings or localization keys are required.
