## 0. Conclusion

**Feasible. Narrowed to the `Gemini Models` group only, the Antigravity integration in v0.4.5 becomes a new-provider job with zero schema change and zero view change.**

Four reasons:

1. `gemini-weekly` is the only bucket on this account that carries **both** a percentage and a reset time. The two `3p` buckets' `resetTime` is **not provided** (the key does not exist).
2. A single window is a shape this codebase already ships (Zhipu GLM returns exactly one window), so the hero, the secondary row and the Console need no changes.
3. Narrowing makes three earlier plan items disappear: adding `groupName` to `QuotaWindowSnapshot`, the hero's two-window ambiguity, and the UI form for "no reset time provided".
4. The real engineering difficulty is not decoding — it is the **credential shape**. `BalanceRefreshController` short-circuits to `.notConfigured` when the credential is empty, so a decorator must first translate the daemon file into a non-empty credential.

## 2. Scope

### 2.1 In scope

| Item | Detail |
|---|---|
| Data group | **`Gemini Models` only**; the implementation iterates **every** bucket in that group rather than hard-coding `bucketId == "gemini-weekly"` |
| Fields read | `remainingFraction`, `resetTime` |
| Fetch path | ① `~/.gemini/antigravity/daemon/hub_*.json` first; ② `lsof -nP -iTCP -sTCP:LISTEN -F pcn` grouped by pid as fallback |
| Failure tiers | 401/403 = running but signed out; connection refused = not running |
| Provider shape | New `ProviderID.antigravity`, `detailKind: .quotaUsage`, `credentialManagement: .localExternalConfiguration` |

**Why "every bucket in the group" rather than "just `gemini-weekly`":**

- On this account the group holds one bucket, so both spellings are equivalent;
- A paid Pro account's Gemini group carries an extra `gemini-5h`, which group iteration covers **without a code change**;
- A hard-coded bucket id is more brittle (upstream renaming it breaks the provider).

### 2.2 Out of scope, with restart triggers

| Deferred item | Why it is not in v0.4.5 | Trigger to restart it |
|---|---|---|
| **`Claude and GPT models` group** (`3p-weekly` / `3p-5h`) | Both buckets' `resetTime` is **not provided**; both currently report `remainingFraction: 1` (100%), so they add two blank rows and no decision value | Upstream starts returning a `3p` reset time; or users ask for third-party allowance visibility |
| **Model catalog** (13 models + `New`/`Leaving Soon`/`Notice`/`Paid Pro`) | The data lives in a **different RPC** (`GetCascadeModelConfigData`) and is neither money nor a percentage; it belongs in a **parallel subsystem** modelled on `CodexManualResetCreditsProvider`, roughly twice the work of the quota integration | After quota integration is stable, as its own issue |
| **agy CLI fallback** | Three measured problems: the `1970-01-01T00:00:00Z` sentinel, 9–14 seconds per call, and one leftover `agy` process per call | When "read quota with Antigravity closed" is required |
| **Policy for a missing `remainingFraction`** | All three buckets on this account carry the field, so it is **not triggered**; the three candidates (throw / treat as 0% / treat as 100%) must be decided when it actually happens | On integrating `3p`, or on encountering a missing field |
| **Hero "most constrained window" semantics** | Meaningless with one window, and it would change every `quotaUsage` provider — its own step | When several windows must be shown at once |
| **`groupName` on `QuotaWindowSnapshot`** | See 2.3 | Same as the `3p` group |
| Release actions (bump, package, tag) | This file stops at implementation and acceptance | Release stage, per the runbook |

### 2.3 Plan items that narrowing removes

| Earlier plan item | Why it is no longer needed | Evidence |
|---|---|---|
| Adding `groupName` to `QuotaWindowSnapshot` | One group, one window: the flat `windows` array already expresses it | Measured: the group holds one bucket; and `ZhipuCodingPlanProvider.swift:73` already ships `windows: [window]`, with `ZhipuCodingPlanProviderTests.swift:91` asserting `windows.count == 1` |
| Hero's "five-hour first vs most constrained" ambiguity | With one window the two rules are identical, so no ambiguity exists | `MenuBarBalanceViewModel.swift:214-231`: `secondaryQuotaWindowSummary` returns `nil` when `secondary.isEmpty`, so the secondary row never renders |
| UI form for "no reset time provided" (blank vs "not provided") | `gemini-weekly` has a real `resetTime` | Measured: `resetTime = "2026-12-03T15:13:43Z"` |

**One correctness gap must be recorded (acceptable):**

If the Gemini group drains to 0% while the `3p` group still has allowance, v0.4.5 shows "plan exhausted" where Antigravity's UI shows partial availability. The cause is that `ProviderStatusFormatter` reads `usage.isAvailable`, and in v0.4.5 `usage` holds only the Gemini window. The gap disappears when `3p` lands; `3p` is currently at 100%, so it is not a blocker.

**The architectural problem this step must solve (critical):**

`BalanceRefreshController.performRefresh` **short-circuits** on an empty credential, so the provider is never called:

```swift
// Sources/APIInquiryCore/Refresh/BalanceRefreshController.swift
guard let apiKey = try credentialStore.credential(forAccount: credentialAccount),
      !apiKey.isEmpty else {
    state = .notConfigured
    return
}
```

`isCredentialConfigured` (`MultiProviderBalanceCoordinator.swift:105-115`) takes the same path. So **writing the provider alone is not enough**: the Console shows "not configured" and no refresh ever happens.

The fix copies what Codex already does (`CodexCredentialStore` synthesises a credential from `~/.codex/auth.json`): S1 also ships the **encoding and decoding of a credential payload**, so a decorator can hand a non-empty string to `fetchSnapshot(apiKey:)`. Payload shape:

```
{"httpPort":<int>,"csrfToken":"<32-36 chars>","pid":<int>}
```

> **Security:** this payload carries the CSRF token, so it must **never** be printed, written to disk, or placed in a test fixture with a real value. Fixtures always use a fake token. The token changes on every Antigravity restart (measured: the file is rebuilt with the process lifetime), so it is read fresh into memory per refresh and never cached.

### S2 — lsof fallback probing (Core only)

| | |
|---|---|
| **ID** | S2 |
| **Content** | When the daemon file is absent: `lsof -nP -iTCP -sTCP:LISTEN -F pcn` → group by `pid` → **sort each group's ports descending** → probe each until one returns 200 for `RetrieveUserQuotaSummary`. Plain HTTP is preferred over TLS (the RPC listener binds later, so its port number is larger) |
| **Files** | Edit `Sources/APIInquiryCore/Providers/AntigravityLocalSession.swift` (add the `lsof` branch); add parser unit tests |
| **Independent acceptance** | ① Parser unit test against a **recorded lsof text fixture** (`p<pid>` / `c<cmd>` / `n<addr>` line kinds) asserting grouping and ordering; ② one run against real `lsof` output asserting no crash and a non-negative port list; ③ **negative:** lsof output with no Antigravity process → empty list → falls through to `appNotRunning` |
| **Blast radius** | Still S1's new file; no existing code touched |
| **Depends on** | S1 |
| **Rollback** | Remove the `lsof` branch; degraded (daemon-file only) but not broken |
| **Touches UI?** | **No** |

**Measured evidence:**

```
$ lsof -nP -iTCP -sTCP:LISTEN -F pcn | head -6
p674
crapportd
f11
n*:56329
f12
n*:56329
```

Each process is `p<pid>` followed by `c<command name>`, then one `f<fd>` + `n<address>` pair per socket. The parser skips `f` lines and takes the port from the tail of each `n` line.

**Why sort descending within a group:** measured, Antigravity's `httpsPort = 63421` / `httpPort = 63422`, and agy's `53870` / `53871` — the plaintext RPC port number is always larger. Descending order therefore reaches the plaintext listener first and avoids sending a plaintext request to a TLS listener.

**Why map `"weekly"` → `"Week"` inside the provider instead of changing `QuotaWindowKind(label:)`:**

The existing mapping only accepts a fixed set:

```swift
// Sources/APIInquiryCore/Models/BalanceModels.swift
public init?(label: String) {
    switch label {
    case "5h": self = .fiveHour
    case "Week", "7d": self = .week
    case "Month", "Monthly", "1M": self = .month
    default: return nil
    }
}
```

The API sends `"weekly"` (lowercase), which is **not in the table**; passing it through would put the English word `weekly` into the Chinese UI. But `QuotaWindowKind(label:)` is relied on by Codex's `"Week"`, so changing it is a cross-provider change. Under the incremental rule, **normalise to the canonical label inside the provider** and leave the shared mapping alone.

**Measured shape of `resetAt`:**

| Bucket | `resetTime` |
|---|---|
| `gemini-weekly` | `"2026-12-03T15:13:43Z"` |
| `3p-weekly` | **not provided** (key absent) |
| `3p-5h` | **not provided** (key absent) |

Because only the Gemini group is read, v0.4.5's `resetAt` is always non-nil, so "not provided" needs no handling here.

## 4. Dependencies and order

```
S1 ──► S2 ──┐
            ├──► S3 ──► S4a ──► S4b ──► S5
S1 ─────────┘
```

- S2 depends on S1 (same file, same error type).
- S3 depends on S1 (needs the session payload) and **not on S2** — if the daemon file is readable, `lsof` is never needed.
- **S2 can merge later:** S1 + S3 + S4 already cover this account's happy path. S2 is a robustness increment and can land after S4 without blocking S5.

### 4.1 Why the Gemini group alone carries the first version

| Dimension | What the Gemini group gives | Sufficient? |
|---|---|---|
| Primary number | `0.5508368` → `55%` remaining | The panel's and menu bar's core need |
| Reset time | `2026-12-03T15:13:43Z` → `12/03` | A real date, not a sentinel |
| Availability | `remainingPercentage > 0` → plan available | Status line works |
| Menu bar title | `.week` → bare percentage | Existing path |

**One bucket answers both "how much is left" and "when does it refill".** That is exactly why the panel exists. Conversely, the `3p` group is `100% / 100%` with `resetTime` **not provided**, so adding it would produce two blank rows and no decision value.

### 4.2 Why deferring `3p` does not block later work

| Guarantee | Detail |
|---|---|
| The transport layer needs no rewrite | S1/S2 produce a session (port + token), independent of how many buckets are decoded. Adding `3p` later touches only S3's group filter |
| `groupName` is only needed then, so not adding it now is correct | An optional field on `QuotaWindowSnapshot` is purely additive (defaulting to `nil` keeps `Equatable` compatible). Adding it when two dimensions actually exist avoids pre-building an extension point nothing uses |
| The model catalog is fully orthogonal | It is a parallel subsystem (cf. `CodexManualResetCreditsProvider`) that never touches `QuotaUsageSnapshot`, so it can ship in a later version |

## 5. Risks and mitigations

### 5.1 Stale daemon file

| | |
|---|---|
| **Symptom** | After a crash or `kill -9`, `hub_*.json` can remain on disk while the port is closed |
| **Measured** | On a normal exit the directory is emptied: `~/.gemini/antigravity/daemon/` became an empty directory at `Nov 27 16:49:07`. Connecting to a closed port returns `curl: (7) Failed to connect to 127.0.0.1 port 63499` |
| **Mitigation** | ① Verify the pid is alive after reading (`kill(pid, 0)`); ② check `lsVersion` for compatibility; ③ when the port is unreachable report `appNotRunning`, **not** "not configured"; ④ with several `hub_*.json` files, take the newest mtime whose pid is alive |

### 5.2 Port probe picking the wrong listener

| | |
|---|---|
| **Symptom** | With several products running (App + IDE + agy), a plaintext JSON request can land on a TLS listener |
| **Measured** | Plaintext to a TLS listener returns `Client sent an HTTP request to an HTTPS server.` + `HTTP 400`; a tokenless RPC on agy returns `HTTP 401` |
| **Mitigation** | ① Group by `pid` and **sort each group's ports descending** (measured: the http port number is always larger than https); ② actually probe each candidate with `GetUserStatus` or `RetrieveUserQuotaSummary` and accept only 200; ③ when everything fails, follow ai-usagebar's lesson and **prefer reporting "running but signed out"**, because that is actionable, while a refused connection only means it is not running |

### 5.3 Permissions and token expiry

| | |
|---|---|
| **Symptom** | The daemon file is `0600` and user-private; the CSRF token changes when the process is rebuilt |
| **Measured** | `stat` → `-rw-------`, `csrfToken` is 36 characters; a tokenless request returns `{"code":"unauthenticated","message":"unauthenticated: missing CSRF token"}` `HTTP 401` |
| **Mitigation** | ① Re-read the file on every refresh and **never cache the token**; ② map 401/403 to "running but signed out" with a retry action, never "replace key" (this provider has no key to replace); ③ the app is not sandboxed (`codesign -d --entitlements - "/Applications/API Inquiry.app"` shows no `app-sandbox`), so reading `~/.gemini` needs no extra permission; ④ the token stays in memory only — **never printed, never written, never in a fixture** |

### 5.4 Other

| Risk | Mitigation |
|---|---|
| The private RPC changes with an Antigravity release | Record `lsVersion` in the error copy; on 404 or non-JSON, classify as `versionChanged` and say "Antigravity was upgraded" rather than "not configured" |
| Bucket count is not fixed | Iterate the group and **never assume** `gemini-5h` exists; an empty group becomes `missingBalanceInfo` |
| A paid account adds `gemini-5h`, producing two windows | The hero already takes the first `.fiveHour` window, so the behaviour holds automatically; confirm once in S5 with `--fixtures` |
| Regression in the five existing providers | Every step must confirm their snapshot fields are unchanged before merging (see §6) |

### A.3 Number conversion

```
0.5508368 × 100              = 55.0836800
truncate(scale: 0, .down)    = 55
```

`ProviderValueFormatter.formatPercentage` always goes through `truncate` + `NSDecimalRound(.down)`, so the shown value never exceeds what is actually left.
