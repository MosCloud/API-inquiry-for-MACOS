# API Inquiry v0.4.0

## New Features

- **OpenCode support**: the menu bar and Console now show OpenCode usage (5-hour / weekly / monthly), and the Console API page can open OpenCode's own config file.
- **DeepSeek granted balance**: the DeepSeek card now separates granted credit from topped-up credit, and the old "Detail" metric is renamed "Total balance".
- **Stale values are marked**: when a refresh fails, the menu bar number is marked as stale instead of passing old data off as current.
- **Copy build info**: click the version label in Console to copy the commit of the build you are running.

## App Optimization

- **A shorter panel**: the hero area keeps only the current window and folds the rest into one summary line, cutting the panel height by about 18% with no information lost.
- **One grid for every provider**: secondary providers share the same three columns (window / remaining / reset), and balance providers line their amount and currency up with them. Columns shrink to their content instead of reserving fixed space.
- **One type size**: values and labels now share a size and weight, so numbers no longer render at different sizes. A long provider name gives way first; the numbers never shrink.
- **Status wording that matches the product**: subscription plans read "Plan available / Plan exhausted", prepaid balances read "Available / Balance low", instead of one vocabulary for both.
- **More reliable refreshing**: rapid refreshes and key saves are coalesced rather than dropped, so the UI no longer sticks on old data.
- **Small inconsistencies fixed**: Zhipu's menu bar label shows only the percentage, its localisation is complete, warning colours match the other providers, and every logo is scaled on one optical baseline so the four wordmarks finally read the same size.

## Bug Fixes

- Removed the stray "Plan Next Resets" column that appeared only on the Zhipu card in Console Home.
- Fixed a launch crash when a provider image was missing.
- Fixed the Codex local-configuration hint disappearing once OpenCode joined the credential chain.
- Fixed credential failures for Codex and OpenCode pointing somewhere other than their own CLI.

## Known limitations

- Apple notarization is not enabled yet; the first launch may need approval under System Settings → Privacy & Security.
- Codex and OpenCode usage depends on the login state of their local CLIs; if credentials expire, sign in again with the CLI.
- DeepSeek's granted balance only appears when the API returns that field.
